# Proverbs ピースソルバー 実装仕様書

## 1. プロジェクト概要

### 1.1 目的
Steam版パズルゲーム「Proverbs」の1ピース単位のマインスイーパー系パズルを解くWebアプリケーション。ユーザーがピースの形状と数値ヒントを入力すると、システムが解を計算しテキストアートで表示する。

### 1.2 パズルのルール
- ピースは不規則な形状（有効セルの集合）で構成される
- 一部のセルには数値（0〜9）が書かれている
- 数値は「自セルを含む3×3範囲内で、塗るべきセル数」を示す
- 数値が書かれたセル自身も「塗る/塗らない」の決定対象である（数値のカウントには自セルの塗り状態も含まれる）
- 3×3範囲がピース外にはみ出す場合は、はみ出した分は無視（ピース内のセルだけカウント）
- 全ての数値制約を満たすように、各セルを「塗る」か「塗らない」か決定する

## 3. 機能要件

### 3.1 ソルバー機能（コア）
- **入力**: セル集合 + 数値ヒント辞書
- **処理**:
  1. 確定ルール適用（filled == clue → 残りは空、unknown + filled == clue → 残りは塗る）
  2. 制約伝播（複数ヒントの3×3範囲重なりから推論）
  3. バックトラッキング（1と2で解けない場合、仮定して探索）
- **出力**: 各セルの状態（塗る=1 / 塗らない=0）
- **解の一意性**: 複数解がある場合は最初に見つけた解を返し、警告フラグを立てる（「最初に見つけた解」の定義は 6.5 の探索決定性による）
- **解なし検出**: 制約を満たす割り当てが存在しない場合は `no_solution` を返す。伝播中に矛盾を検出した場合は、最初に矛盾したヒントの位置を `firstConflict` として結果に含め、入力ミスの特定を助ける

### 3.2 UI機能
1. 形状入力（テキストエリア + グリッドクリック両対応）
2. 数値ヒント入力（グリッドのセルをクリックして数値入力）
3. 解答表示（テキストアート + グリッドビュー）
4. undo/redo（操作単位）
5. 画像出力（PNG）
6. サンプル問題プリセットのロード（3問以上）

## 4. UI/UX 設計

### 4.1 画面構成
1画面完結型のシングルページ。上から順に以下のセクションを配置：

```
┌─────────────────────────────────────┐
│ ヘッダー（タイトル + サンプル読込 +      │
│           Undo/Redo/Reset）           │
├─────────────────────────────────────┤
│  Step 1: ピース形状入力                │
│  グリッドサイズ: 幅 [10] × 高さ [10]    │
│  ┌────────────┬────────────┐        │
│  │ テキスト入力 │ グリッド表示 │        │
│  │ (# と .)   │ (クリック編集)│        │
│  └────────────┴────────────┘        │
├─────────────────────────────────────┤
│  Step 2: 数値ヒント入力                │
│  グリッドのセルをクリック→数値入力       │
│  （右クリックで削除、キーボード0-9対応）  │
├─────────────────────────────────────┤
│  Step 3: 解答                         │
│  [解く] ボタン                        │
│  ┌────────────┬────────────┐        │
│  │ グリッド表示 │ テキストアート│        │
│  │            │ (コピー可能)  │        │
│  └────────────┴────────────┘        │
│  [PNG出力] ボタン                     │
└─────────────────────────────────────┘
```

Step 1〜3は縦に並列表示（切替なし）。Step 1・2 の変更はグリッド表示に即座に反映される。ただし解答（Step 3）は形状・ヒントの変更時に自動クリアされ、再度「解く」を実行するまで表示されない（5.2参照）。

- **サンプル読込**: ヘッダーのドロップダウンからプリセット問題（3問以上）を選択してロードする。ロードは形状＋ヒントの一括置換で、1つのundo単位として記録する。プリセットのデータはテストで使うサンプル問題と同一のJSON形式（10.2参照）
- **グリッドサイズ**: Step 1 に幅・高さの数値入力（各1〜20）を置く。初期サイズは 10×10、上限は 20×20 固定。縮小により範囲外となるセル・ヒントは自動削除する（サイズ変更と合わせて1つのundo単位）

### 4.2 表示凡例
- 有効セル（未確定）: 白マス `□`
- 塗るセル: 黒マス `■`
- 塗らないセル: バツ印 `×`
- 数値ヒント: 中央に数字を表示。塗り状態と両立して表示する：
  - ヒント＋塗る: 黒背景に白文字の数字
  - ヒント＋塗らない: 白背景に数字、右上に小さな×
  - ヒント＋未確定: 白背景に数字のみ
- 無効ヒント（値が近傍のピース内セル数を超えるもの）: 赤枠＋警告表示（4.4参照）
- ピース外: 表示なし（背景色）
- カーソル/選択中: ハイライト

### 4.3 テキストアート仕様
- 形状入力/出力の記号：
  - `#` : 有効セル
  - `.` : ピース外
- 解答表示のテキストアート（**1セル＝全角1文字幅**に統一して桁を揃える）：
  - `■` : 塗る（ヒントなし）
  - `×` : 塗らない（ヒントなし）
  - `？` : 未確定（解けなかった場合。全角）
  - ピース外: 全角スペース（`　`）
  - ヒントセルは数字と塗り状態を1文字で両立させる：
    - ヒント＋塗る: 黒丸数字 `⓿❶❷❸❹❺❻❼❽❾`
    - ヒント＋塗らない: 白丸数字 `⓪①②③④⑤⑥⑦⑧⑨`
    - ヒント＋未確定: 全角数字 `０１２３４５６７８９`
  - 注意: `■` `×` や丸数字は East Asian Width が Ambiguous のため、フォントによっては半角幅で描画される。テキストアートビューには日本語等幅フォントを明示指定し、全角幅で揃うことを前提とする

### 4.4 操作性
- グリッドは最大 20×20 セル（ハードキャップ）。初期サイズは 10×10
- クリック操作:
  - Step 1: 左クリックで有効/無効トグル（ヒント付きセルを無効化した場合、そのヒントも同時に削除される。5.2参照）
  - Step 2: 左クリックで数値入力モードON、数字キーで入力、Deleteで削除
- ヒント値の即時検証: 入力値がそのセルの近傍（3×3∩ピース内）のセル数を超える場合は**入力を拒否し、その場で警告を表示**する（解く実行時まで持ち越さない）。形状編集の結果、既存ヒントが超過状態になった場合は該当セルを赤枠でハイライトし、解消されるまで「解く」ボタンを無効化する
- キーボードショートカット:
  - Ctrl+Z / Ctrl+Y : Undo / Redo（Macは Cmd+Z / Cmd+Shift+Z）
  - Ctrl+Enter : 解く実行

## 5. データモデル

### 5.1 型定義（TypeScript）

```ts
// セル座標
type CellPos = { x: number; y: number };

// セル状態（解答）
type CellState = 'filled' | 'empty' | 'unknown';

// ピース形状
type PieceShape = {
  width: number;  // グリッド（キャンバス）の幅。1〜20
  height: number; // グリッド（キャンバス）の高さ。1〜20
  cells: Set<string>; // "x,y" 形式でSetに格納（座標のシリアライズ）
                      // 不変条件: 0 <= x < width, 0 <= y < height
};

// 数値ヒント
type Clues = Map<string, number>; // "x,y" → 数値

// 解答
type Solution = Map<string, CellState>; // "x,y" → 状態

// ソルバーの実行結果
type SolveResult = {
  status: 'solved' | 'multiple_solutions' | 'no_solution';
  solution: Solution | null;   // no_solution のときは null
  firstConflict?: CellPos;     // 矛盾を最初に検出したヒントの位置（入力ミス特定の補助）
};

// アプリ全体の状態
type AppState = {
  shape: PieceShape;
  clues: Clues;
  solution: Solution | null;
  solverStatus: 'idle' | 'solved' | 'no_solution' | 'multiple_solutions';
};
// 備考: ソルバーは同期実行のため 'solving' 状態は持たない（将来非同期化する場合に追加）。
// 「矛盾」は「解なし」の一形態として no_solution に統一し、firstConflict の有無で区別する。

// 履歴管理用アクション
type Action =
  | { type: 'TOGGLE_CELL'; pos: CellPos }
  | { type: 'SET_CLUE'; pos: CellPos; value: number }
  | { type: 'REMOVE_CLUE'; pos: CellPos }
  | { type: 'SET_GRID_SIZE'; width: number; height: number }
  | { type: 'LOAD_TEXT_ART'; text: string }
  | { type: 'LOAD_PRESET'; presetId: string }
  | { type: 'SOLVE' }
  | { type: 'RESET' };
```

### 5.2 状態管理
- `useReducer` でメイン状態を管理
- 履歴スタック（past / present / future）でundo/redo実装
- ソルバー呼び出しは同期実行だが、UIブロックを避けるため小さいピース想定でOK
- **ヒントの不変条件**: ヒントは有効セル上にのみ存在できる。セルの無効化・グリッド縮小・テキストアートロード・プリセットロードにより無効セルとなった位置のヒントは、同一アクション内で自動削除する（形状変更とヒント削除で1つのundo単位）
- **解答の無効化**: 形状またはヒントを変更するアクション（TOGGLE_CELL / SET_CLUE / REMOVE_CLUE / SET_GRID_SIZE / LOAD_TEXT_ART / LOAD_PRESET）は `solution` を null に、`solverStatus` を 'idle' に自動リセットする

## 6. ソルバーアルゴリズム詳細

### 6.1 段階1: 確定ルール
各ヒント `(cx, cy) = clue` について：
- `neighbors` = (cx, cy) を中心とする3×3範囲のうちピース内のセル
- `filled_count` = 塗り確定セル数
- `unknown_count` = 未確定セル数
- ルールA: `filled_count == clue` → 未確定セルはすべて `empty`
- ルールB: `filled_count + unknown_count == clue` → 未確定セルはすべて `filled`

変化がなくなるまで繰り返し。

### 6.2 段階2: 制約伝播（枝刈り最適化）
段階2は探索の**枝刈り最適化**であり、解の正しさは段階1＋段階3で完全に担保される（段階2の推論が弱くても結果は変わらず、探索速度のみに影響する）。

最低限、以下の**サブセットルール**を実装する。ヒントXについて `unk(X)` = X近傍の未確定セル集合、`rem(X)` = clueX − X近傍の塗り確定数 とする。重なり合う2つのヒント A, B が `unk(B) ⊆ unk(A)` を満たすとき：
- `rem(A) − rem(B) == |unk(A) − unk(B)|` → `unk(A) − unk(B)` のセルはすべて `filled`
- `rem(A) == rem(B)` → `unk(A) − unk(B)` のセルはすべて `empty`

より一般の推論（共通部分 `unk(A) ∩ unk(B)` に入りうる塗り数の上限/下限を互いの制約に射影して突き合わせる）は任意実装とする。10.1 の「制約伝播が必要なケース」のテストは、サブセットルールで確定が進むケースとする。

### 6.3 段階3: バックトラッキング
段階1・2で解けなかった場合：
1. 未確定セルの中から「関与するヒント数が最大のセル」を選ぶ（同数の場合は走査順=6.5で最初のセル）
2. そのセルを `filled` と仮定して段階1・2を再実行
3. 矛盾したら `empty` と仮定して再実行
4. 両方矛盾したら親のバックトラック
5. 解が見つかったら、別解があるかも確認（複数解検出のため2つ目まで探索。2つ目が見つかった時点で探索を打ち切る）

### 6.4 矛盾検出
どのタイミングでも以下をチェック：
- `filled_count > clue` → 矛盾
- `filled_count + unknown_count < clue` → 矛盾

仮定なし（探索木の根）での矛盾も、全探索の結果解が存在しない場合も、いずれも `no_solution` として報告する。仮定なしの伝播中に最初に矛盾を検出したヒントの位置を `firstConflict` に記録して返す（探索中の仮定下での矛盾は記録しない）。

### 6.5 探索の決定性
同一入力に対して常に同一の結果を返すため、以下を固定する：
- セル・ヒントの走査順は行優先（y昇順、同一行内はx昇順）
- 分岐セルの選択は 6.3 のヒューリスティック、同点時は走査順で最初のセル
- 仮定は `filled` → `empty` の順に試す

複数解の場合に返す「最初に見つけた解」は、この探索順で最初に到達する解と定義する。これによりテストで解の内容を検証できる。

## 7. undo/redo 仕様

### 7.1 対象
以下のユーザー操作をhistoryに記録：
- セルのON/OFFトグル
- 数値ヒントの追加/変更/削除
- テキストアート全体ロード
- 「解く」実行（解の状態変化を含む）
- リセット

### 7.2 実装方針
- immerを使うと状態のコピーが楽（推奨）
- history stack: `{ past: AppState[]; present: AppState; future: AppState[] }`
- 上限: 50件程度でOK
- Ctrl+Z / Ctrl+Y のキーバインド
- ボタンUIも用意

## 8. 画像出力機能

### 8.1 出力内容
解答済みグリッドをPNGとして出力：
- 塗るセル: 黒塗り
- 塗らないセル: バツ印
- ヒント: 数字
- ピース外: 透過またはグレー背景
- グリッド線あり
- タイトル/日時（オプション）

### 8.2 実装方針
- Canvas APIで描画してPNG化（追加ライブラリなしで実装する）
- ダウンロードボタンで保存

## 10. テスト

### 10.1 ソルバーのユニットテスト（必須）
最低限、以下のケースをカバー：
- 単純な3×3全塗り（ヒント=9）
- 単純な3×3全空き（ヒント=0）
- 確定ルールで解ける中規模ケース（5×5）
- 制約伝播（サブセットルール）が必要なケース
- バックトラッキングが必要なケース
- 複数解のケース（返される解が 6.5 の決定性により一意に定まることも確認）
- 解なしケース（即時に矛盾するケースと、探索の結果解が存在しないケースの両方。`firstConflict` の報告も確認）
- ヒントセル自身が塗りになるケース（1.2のルール確認）

### 10.2 サンプル問題
UIプリセット用のサンプル問題は `src/presets/` に JSON形式で保存し（3問以上）、READMEで解説。テストも同じJSONを読み込んで検証する。解なし・複数解などUIプリセットに不向きなケースは `tests/fixtures/` に置く。
