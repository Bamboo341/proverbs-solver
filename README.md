# Proverbs ピースソルバー

Steam版パズルゲーム「Proverbs」の1ピース単位のマインスイーパー系パズルを解くWebアプリケーションです。ピースの形状と数値ヒントを入力すると、ソルバーが解を計算し、グリッドとテキストアートで表示します。

- 仕様書: [docs/Spec.md](docs/Spec.md)

## パズルのルール

- ピースは不規則な形状（有効セルの集合）で構成される
- 一部のセルには数値（0〜9）が書かれている
- 数値は「自セルを含む3×3範囲内で、塗るべきセル数」を示す（ピース外にはみ出た分は数えない）
- 数値が書かれたセル自身も「塗る/塗らない」の決定対象
- すべての数値制約を満たすように、各セルを「塗る」か「塗らない」か決定する

## セットアップ

```bash
npm install
npm run dev    # 開発サーバーを起動（表示されるURLをブラウザで開く）

```

## 使い方

画面は上から Step 1 → 2 → 3 の1画面構成です。上のステップの変更はグリッド表示に即座に反映され、形状・ヒントを変更すると解答は自動的にクリアされます。

### Step 1: ピース形状入力

- **テキスト入力**: `#` = 有効セル、`.` = ピース外。テキストとグリッドは双方向に同期します
- **グリッドクリック**: 左クリックでセルの有効/無効を切り替え
- **グリッドサイズ**: 幅・高さを 1〜20 で指定（初期 10×10）。縮小で範囲外になったセル・ヒントは自動削除されます
- ヒント付きセルを無効化すると、そのヒントも同時に削除されます（1回のundoで両方戻ります）

### Step 2: 数値ヒント入力

- セルをクリックして選択し、**数字キー（0〜9）** で入力
- **Delete キーまたは右クリック**で削除
- そのセルの3×3範囲内のセル数を超える値は入力時に拒否され、警告が表示されます
- 形状変更で既存ヒントが超過状態になった場合は赤枠で表示され、解消するまで「解く」は実行できません

### Step 3: 解答

- **［解く］ボタン**（または **Ctrl+Enter**）でソルバーを実行
- 結果表示:
  - 解けました（一意解）
  - 複数の解があります（最初に見つけた解を表示）
  - 解が存在しません（矛盾を検出したヒント位置を赤枠で明示）
- 解答はグリッドと**テキストアート**（コピー可能）の両方で表示されます
- **［PNG出力］ボタン**で解答を画像としてダウンロードできます（タイトル・日時つき）

### サンプル読込

ヘッダーのドロップダウンからサンプル問題をロードできます:

| サンプル | 内容 |
|---|---|
| 基本（確定ルールだけで解ける） | 各ヒントの過不足だけで順に確定できる5×5 |
| 制約伝播が必要な問題 | ヒントの重なりの差分に着目して解く1×4 |
| バックトラッキングが必要な問題 | 伝播では1マスも確定せず探索が必要な3×3（一意解） |

### Undo / Redo

- **Ctrl+Z / Ctrl+Y** またはヘッダーの「元に戻す / やり直す」ボタン
- セル編集・ヒント編集・ロード・解く・リセットが履歴対象（上限50件）

## テキストアートの記号（解答表示）

1セル＝全角1文字幅で桁が揃います（日本語等幅フォント前提）:

| 記号 | 意味 |
|---|---|
| `■` | 塗る |
| `×` | 塗らない |
| `？` | 未確定（解けなかった場合） |
| 全角スペース | ピース外 |
| `❶❷…⓿`（黒丸数字） | ヒントセルで塗る |
| `①②…⓪`（白丸数字） | ヒントセルで塗らない |
| `１２…０`（全角数字） | ヒントセルで未確定 |

## CLI

問題JSONを直接ソルバーに渡して実行できます:

```bash
npm run cli -- src/presets/backtrack.json
npm run cli -- <problem.json> --no-propagation   # 制約伝播を無効化（検証用）
```

問題JSONの形式（`src/presets/` および `tests/fixtures/` を参照）:

```json
{
  "id": "example",
  "name": "サンプル問題",
  "shape": ["###", "#.#"],
  "clues": { "1,0": 3 }
}
```

- `shape`: `#` = 有効セル、`.` = ピース外の行の配列
- `clues`: `"x,y"`（0始まり）→ ヒント値

## ソルバーの仕組み

1. **確定ルール**: 各ヒントの塗り数の過不足から確定できるセルを埋める
2. **制約伝播（サブセットルール）**: 重なり合うヒントの差分から確定する（枝刈り最適化。正しさは 1+3 で担保）
3. **バックトラッキング**: 仮定を置いた深さ優先探索。複数解検出のため2つ目の解まで探索する

探索順序は決定的で、同一入力には常に同一の結果を返します。詳細は [docs/Spec.md](docs/Spec.md) の6章を参照してください。

## 開発

- 技術スタック: Vite + React + TypeScript + Tailwind CSS v4 + Vitest
- 主要ディレクトリ:
  - `src/solver/` — ソルバー本体（UI非依存）
  - `src/state/` — reducer と undo/redo 履歴管理
  - `src/components/` — UIコンポーネント
  - `src/presets/` — サンプル問題（UIプリセット兼テストデータ）
  - `tests/` — ユニットテスト
